# 更新 v0.18.4 並保留繁中與 MinIO

狀態：應用服務已部署並驗證。使用者已確認升級、部署及保留繁中。

## 背景與證據

- 原分支 `test/work-item-6` 的 `9860fc0` 與 v0.8.0 檔案內容一致。
- 目標為 GitHub 正式 release v0.18.4，commit `b0d1e01d75c2b8efb5730b0e30f351e0f180f57b`。
- 本地繁中包含語系設定、語系選單測試及 9 個 JSON。整合前已在 `79f3419` 提交保全。
- 正式環境使用 `deploy/docker-compose.prod.yml`、忽略版本控制的 `.env.local`，Web 為自建映像；MinIO 使用 `paca_minio_data` volume。
- 新版 production compose 預設使用 RustFS，API 啟動會自動執行 migration，包含移除欄位及搬移後刪除活動表。
- 官方升級腳本要求 `docker-compose.yml` 和 `.env`，與本機部署佈局不同，且預設移除 orphan 容器及清理舊映像。

## 方案與取捨

1. 同時切換 RustFS：符合上游預設，但需要物件層資料搬移與額外驗證，擴大這次升級範圍；不能直接共用 MinIO 的磁碟資料。
2. 保留 MinIO，整合新版原始碼並自行建置繁中 Web：沿用附件、秘密值及資料 volume；需維護一個小型 Compose override，後續啟動要同時載入。

採用方案 2。`deploy/docker-compose.minio.yml` 保留舊服務定義與 volume，將 RustFS 放入未啟用的 profile，並設定新版閘道的 `STORAGE_UPSTREAM=minio:9000`。應用映像固定為 0.18.4；Web 使用包含本地繁中的專用映像。

## 風險與緩解

- 資料庫變更不可只靠切回映像回滾：先完成獨立還原與遷移演練，切換前再次備份並停止舊寫入服務。
- 舊 ai-agent 與新 runner 共用任務來源：切換時先停止舊 ai-agent，不讓兩者並行消費事件。
- 繁中非上游內建語系：保留 zh-TW 註冊、依上游英文結構補翻，沿用既有 locale 結構測試並增加實際切換驗證。
- 保留 MinIO 時新版 gateway 預設仍指向 RustFS：override 同步設定儲存 upstream，驗證代理健康端點。
- 不暴露秘密值：備份目錄與包含設定的檔案限制讀取權限，日誌只輸出必要狀態；不提交 `.env.local`。
